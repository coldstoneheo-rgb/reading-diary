## 오너의 비전(원문 요지)

기억 서랍을 한 단어로 하면 **지식 연결망**이다. 밑줄 문장·인상 깊은 단락을 찍어 올리면 맥락을 파악하고 키워드를 자동 추출·링킹한다.
기록 검색으로 읽었던 책의 기록을 찾고, **같은 키워드가 여러 책에서 발견되면 각 책에서 내가 어떻게 생각했는지 비교**할 수 있다.
AI와 RAG를 결합해 "내 독서 기록을 스스로 연결하는 지식 그래프"를 만드는 것이 목표이며, 이 독서 지식 베이스를 옵시디언에 연동한다.

**오너 추가 지시(2026-09-07):** 옵시디언 연동은 **앱 사용자의 선택**이다. 기록에 집착하는 사용자는 개인 지식망에 편입시키려 하겠지만,
일반 사용자는 앱 안에서 과거 지식을 검색하고 **그때 내 메모**를 확인하는 것으로 충분하다.
**A 책을 떠올리며 키워드를 검색했는데 B 책에서도 그 키워드와 본인이 기록한 독서 메모가 나오는 경험**이 색다르고 새로운 인사이트를 준다.
→ **앱 안의 비교 경험이 모두를 위한 핵심이고, 옵시디언은 옵트인 부가 기능이다.**

## 용어 층위 (안건 1)

오너가 한 스택처럼 말한 다섯은 층이 다르다. 이 구분이 나머지 결정의 전제다.

| 용어 | 정체 | 이 앱에서 |
|------|------|-----------|
| NotebookLM | 서버 제품 | 대체 대상이 아니라 경쟁자. 서버·계정·요금이 전제라 ADR-001·002와 충돌 |
| Obsidian | 로컬 마크다운 노트 앱 | 대체 불가한 **목적지**. 상호운용 대상은 앱이 아니라 `.md` + `[[위키링크]]` + YAML frontmatter |
| RAG | 기법(검색 + **LLM 생성**) | **생성이 없으면 RAG가 아니다.** 현재 기억 서랍에 생성은 0이므로 이것은 검색이다 |
| Vector DB | 임베딩 저장소 | 글자가 달라도 뜻이 비슷한 것을 찾는 문제. 이 규모에서는 불필요(아래 Q2) |
| Knowledge Graph | 노드·엣지 데이터 모델 | 명시적 관계를 정확히 저장. **`KeywordLinks`가 이미 만들고 있는 것** |

## 결정

| 질문 | 합의 | 근거 요약 |
|------|------|-----------|
| Q1 이 기능의 핵심 | **앱 안의 "책 사이 비교"**가 모두를 위한 핵심. 옵시디언 내보내기는 옵트인 부가 기능 | 오너 지시. 일반 사용자는 앱 안에서 끝나고, 기록 집착 사용자만 볼트로 가져간다 |
| Q2 임베딩·벡터 DB | **하지 않는다.** 일기 1,000건은 전체 100KB 규모라 전수 비교가 밀리초다. 병목은 인덱스가 아니라 **모델 크기** | 다국어 소형 임베딩 모델 크기 추정이 5~100MB로 전문가 간 갈림(둘 다 추정, 실측 필요). 어느 쪽이든 지금 지불할 값이 아니다. `isMinifyEnabled = false`라 통째로 실린다 |
| Q3 키워드 정확도 | **사전 기반 규칙**으로 올린다. 명사 완전 일치 화이트리스트, 용언 어미 목록, 조사 목록. 형태소 분석기는 배제.<br>**Q3 수정(2026-09-07, PR #23):** 회의가 지시한 "'과'로 끝나는 명사 꼬리 목록"은 **채택하지 않는다.** 근거: `결과·효과·성과`는 전부 2글자라 1글자 조사 규칙(3글자 이상)에 애초에 걸리지 않아 실익이 합성어뿐인데, 꼬리를 `endsWith`로 보호하면 `생각도`·`정도로`·`여성의`가 통째로 살아남아 같은 낱말이 조사에 따라 갈라진다. 그 형태가 합성어보다 훨씬 흔하므로 `연구결과`→`연구결`을 감수하고 **보호를 완전 일치로 좁혔다**(한계는 테스트로 고정) | 사전 3종은 상수 10KB 남짓이라 APK 영향이 사실상 0이고 100% JVM 테스트 가능. 예상 6~7할 → 8할대(추정) |
| Q4 그래프 저장 | **파생 계산 유지.** Room 테이블을 추가하지 않는다 | 저장/파생의 경계는 "재현 가능한가" 하나다. 알고리즘 산출물은 추출기를 고치면 다시 계산되므로 저장하면 낡는다. 재현 불가능한 것은 사용자가 손으로 만든 판단뿐이고, 그것도 지금은 `#태그`로 컬럼 없이 된다 |
| Q5 비교 화면 | 검색 결과를 **책별로 묶고**, 각 책에서 **내 메모를 발췌보다 앞에** 놓는다. 두 권 이상이면 그 사실 자체를 머리말로 먼저 보여준다 | 비교의 대상은 문장이 아니라 그때의 생각이다. 평면 리스트로 섞으면 "다른 책에서도 나왔다"는 사실이 눈에 띄지 않는다 |
| Q6 옵시디언 | **SAF 내보내기만.** 사용자가 고른 폴더 아래 전용 하위 폴더에, 책당 1파일. frontmatter + 본문 `[[키워드]]` + 인덱스 노트 1장. **키워드 스텁 노트를 만들지 않는다** | 볼트에 이미 그 노트가 있으면 링크만 걸면 옵시디언이 알아서 잇는다. 빈 스텁 대량 생성이 곧 덤프이고 그래프 오염이다. `obsidian://`는 열기 보조수단이고 쓰기의 주 경로는 SAF다 |
| Q7 볼트 쓰기 안전 | 1단계 쓰기 없음. 2단계는 **새 파일 생성만**, 이미 있으면 건너뛰고 목록에 표시. 덮어쓰기·병합은 3단계 | 데이터베이스가 날아가면 우리 앱 기록을 잃지만, 볼트를 망가뜨리면 사용자가 수년간 쌓은 노트를 잃고 복구 수단이 없다 |
| Q8 이름 | ADR-003 Q6의 금지어를 **조건부 허용으로 바꾼다.** "RAG"는 앱 안에서 LLM이 문장을 생성할 때만 정직하고, 그때도 사용자 대상 용어는 "AI 요약"이다. "옵시디언"은 **내보내기 구현이 소스에 존재할 때만** 허용한다 | 기능이 없으면 단어도 못 쓰는 구조를 유지한 채 문을 연다. `HonestCopyTest`를 지우지 않고 규칙만 조건화한다. **테스트 조건화는 2단계 SAF 내보내기 PR에서 함께 한다** — 구현이 없는 동안은 무조건 금지와 결과가 같으므로 지금 손대지 않는다 |
| Q9 비용 경계 | 기본 경로는 **100% 오프라인**. 선택 경로는 사용자 본인 키로 **텍스트만** 전송. 비용은 전부 키 소유자 | 오너의 낮은 지불 의사는 제약이 아니라 설계 결론이다. 서버 프록시·구독·임베딩 서비스가 모두 탈락하고 온디바이스와 본인 키만 남는다 |

## 보류 — 오너가 결정할 질문

1. 볼트 **병합**(기존 파일 수정)까지 갈 것인가? 2단계의 "새 파일 생성만"에서 멈출 것인가?
2. 텍스트 전용 LLM 키워드 제안을 열 것인가? 열면 **사진 동의와 별개 체크박스**여야 한다. 등급이 다른 동의를 하나로 묶는 것 자체가 문제다.
3. 키워드 정확도를 위해 APK를 몇 MB까지 키울 용의가 있는가? 사전 규칙 8할에서 멈출 것인가, R8 축소를 켜고 재검토할 것인가?
4. Room 마이그레이션을 지금 잡을 것인가, 사용자 편집 키워드가 실제로 필요해질 때까지 미룰 것인가?
5. `GeminiApiClient`의 모델 상수는 ADR-001이 "실재 확인 최우선"으로 표시한 미검증 값이다. 텍스트 경로를 열기 전 확인이 선행 조건.

## 가장 강력한 반대(기록)

- **AI 아키텍트**: 실패 지점은 모델이 아니라 **입력의 희소성**이다. 밑줄 문장은 20~40자이고 메모는 대개 비어 있다. 짧은 두 문장 사이 유사도는 노이즈다. **연결의 상한은 검색 기술이 아니라 사용자가 남긴 글자 수가 정한다.** 투자할 곳은 벡터가 아니라 "왜 좋았는지 한 줄" 입력률이다.
- **Android 엔지니어**: **볼트 쓰기가 전체에서 실패 확률이 가장 높고 피해가 가장 크다.** 병합을 JVM으로 아무리 테스트해도 실제 SAF + 옵시디언 모바일 + 동기화 조합은 오너 기기 한 대에서만 확인된다.
- **PKM·프라이버시**: **"AI + RAG"라는 간판이 이 제품의 유일한 자산을 갉아먹는다.** NotebookLM과 다른 이유는 "사진은 내 기기에만 남는다" 하나다. 생성을 화면 중앙에 놓으면 사용자는 "그럼 내 밑줄은 어디로 가나"를 묻는다. 정직한 온디바이스 연결이 먼저 재미있지 않다면 LLM을 얹어도 재미있어지지 않는다.

## 그럼에도 진행하는 이유

세 반대가 모두 **"먼저 만들 것"을 가리킨다**. 입력 희소성은 비교 화면이 메모를 앞에 놓아 메모를 쓸 이유를 만들 때 줄어든다.
볼트 위험은 1단계에서 쓰기를 하지 않으면 0이다. 이름 문제는 기능이 생길 때까지 단어를 잠가 두면 발생하지 않는다.
따라서 1단계는 세 반대 중 어느 것과도 충돌하지 않으며, 오너 비전에서 **가장 값싼 승리**(스키마 변경 0, 새 의존성 0)다.
