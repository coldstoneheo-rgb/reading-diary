## 오너의 비전(원문 요지)

옵시디언 연동은 배제. 로컬에서 독서 기록·도서 관리·인상 깊은 구절 기록과 "지식망"을 구축한다. A 책의 키워드·문구가 B 책의 키워드와
연결되어 내가 기억하고 싶은 지식의 종류와 키워드를 확인할 수 있고, **서로 다른 책의 지식이 연결되어 머릿속에 입체적인 지식 체계가
만들어져 새로운 인사이트가 나오는 것**이 진정한 독서의 즐거움이다. 연결망 그래프 디자인을 개선한다.

## 보류 — 오너가 결정할 질문

1. **시드 데이터**(3군): 신규 설치의 예시 책 3권·일기 3건을 없애고 빈 상태 온보딩으로 갈까, "예시" 배지가 붙고 통계에서 제외되는 삭제 가능한 샘플 1권을 둘까? 기존 기기의 시드는 어느 쪽이든 삭제하지 않는다. (설계·구현은 제거, 마케팅은 오너 결정 요청 → 보류)
2. **표지 폴백**(3군): Unsplash 스톡 URL 4곳(시드·수동 등록 폴백·`cleanCoverUrl`·OCR 예시)을 네트워크 없는 로컬 플레이스홀더(제목 첫 글자 + 색)로 바꿔도 되는가? 전 화면의 시각 톤이 바뀐다.
3. **사용자 지정 태그의 정식 저장**: `#태그` 규약으로 충분한가, Room 마이그레이션 PR(`fallbackToDestructiveMigration` 제거 + `Migration(2,3)` + `exportSchema=true` + 마이그레이션 테스트, 반나절 이상)을 따로 잡는가?
4. **온디바이스 임베딩**(수 MB 모델)으로 "같은 단어"를 넘어 "비슷한 뜻"까지 연결할 것인가?
5. **백업 정책**: 현재 상태는 **Android Auto Backup에 Room DB·일반 설정이 이미 포함**되어 있다(`allowBackup="true"`, `backup_rules.xml`; 키만 제외). 이대로 유지할지, 끌지, 사용자가 직접 실행하는 내보내기(JSON/마크다운 공유 시트)를 추가할지? 이번 루프는 현 상태를 사실대로 표기만 한다(Q7).
6. **스토어 부제 문구**만 오너 몫("밑줄이 책과 책을 잇는 독서 다이어리" 등). 화면 이름은 Q6대로 "기억 서랍"으로 확정이며 되묻지 않는다. 함께: 마크다운 복사의 `[[책 제목]]` 위키링크 유지 여부.

## 가장 강력한 반대(기록)와 그럼에도 진행한 이유

- **설계**: 검증되지 않은 자동 키워드로 "연결"을 보여주면 비전이 신뢰를 잃는다. "그것 — 데미안 ↔ 사피엔스"가 첫 연결이면 장식 그래프보다 나쁜 후퇴다. → 추출기는 순수 함수 + JVM 테스트로 불용어·조사 케이스를 고정하고, 임계를 보수적으로(다른 책 2권↑, 2글자↑, 불용어 통과) 잡아 "적지만 맞는" 결과를 우선한다. 원문 병렬 표시가 검증 경로.
- **구현**: `fallbackToDestructiveMigration()` + `exportSchema=false` 상태에서 태그 컬럼을 넣으려 DB 버전을 올리면 **앱 업데이트만으로 전체 데이터가 조용히 삭제**된다. → 야간 루프에서 스키마는 절대 건드리지 않는다(보류 3).
- **마케팅**: 정직하게 고치면 앱이 텅 비어 보인다. 제거는 되돌리기 쉽지만 인상은 되돌리기 어렵다. → 빼기 PR마다 대체 문구·빈 상태 안내·정직한 이력을 **같은 PR에** 넣는 것을 합격 조건으로 한다. 없어진 것을 지우는 대신 있는 것(온디바이스 OCR, 책 사이 연결, 마크다운 복사)을 정확한 이름으로 다시 소개한다.

## 회의록(요지)

### 앱 설계
- 찬성: 사용자가 "연결"을 느끼는 순간은 **한 단어를 탭했을 때 서로 다른 두 책의 구절이 나란히 보일 때** 하나다. 현재 화면엔 그 순간이 없다(노드는 일기 6개의 원형 배치, 선은 장식, 탭하면 일기 1건). 노드=책, 엣지=공유 단어, 1차는 리스트. 빈 상태 문구 필수("다른 책에서 구절을 한 개 더 모으면 연결이 나타납니다"). `#태그` 파싱으로 컬럼 없이 사용자 큐레이션 경로 확보. RAG 이름은 부적절.
- 반대: 자동 키워드 품질 미검증 상태의 연결은 신뢰를 잃는다.
- 보류 질문: 태그 정식 컬럼, 캔버스 필요성, 임베딩, 진짜 백업 형태, 표지 플레이스홀더 디자인.

### Android 구현
