# ADR-002: 온디바이스 텍스트 인식(ML Kit) 도입 방식

- 상태: **채택(자율 루프 중 3인 전문가 회의로 결정, 오너 사후 확인 대상)** · 2026-09-05
- 결정 방식: 오너 부재 중 Android 플랫폼 엔지니어 / 프로덕트·UX 책임자(오너 대리) / 보안·프라이버시 엔지니어 역할의 에이전트 3인이
  2라운드 회의(각자 찬성 입장 + 가장 강력한 반대 → 상호 반론 → 합의). 회의록은 이 문서 하단.
- 상위 결정: [ADR-001](ADR-001-gemini-key-and-ocr-cost-model.md) 2단계 A(온디바이스 OCR 기본 경로)의 실행 방식.

## 결정

| 질문 | 합의 | 근거 요약 |
|------|------|-----------|
| Q1 모델 배포 형태 | **언번들**(`play-services-mlkit-text-recognition-korean`)로 시작. 매니페스트 자동 다운로드 메타데이터는 넣지 않음 | 레포에 ABI split/AAB 설정이 없어 번들이면 범용 APK 기준 약 +16MB(추정). 배포 형태 변경은 오너 영역. 언번들→번들은 좌표 한 줄 교체라 되돌림 단위가 가장 작음. 사진은 어느 쪽도 기기 밖으로 나가지 않음 |
| Q2 가짜 예시 문장 폴백 | **제거.** 인식 실패·빈 결과는 `OcrState.Error`로 정직하게 표시 + [직접 입력] 경로. 예시는 저장 불가한 입력창 placeholder(중립 문장 1개)로만 | 가짜 인용문이 일기에 저장되는 데이터 오염은 코드 롤백으로 복구 불가. 하드코딩 "일치율 99.8%"·"완벽하게 인식" 토스트도 제거 |
| Q3 Gemini 경로 | 이번 PR은 **ML Kit만**. `GeminiApiClient`는 남기되 어떤 경로에서도 호출되지 않음을 테스트로 고정. "정밀 분석(사진이 Google로 전송됨)" 버튼은 설정 키 UI PR에서 1회 명시 동의와 함께 | 키 UI가 없어 지금은 도달 불가. 키 등록 ≠ 이 사진 전송 동의 |
| Q4 텍스트 합치기 | 자체 데이터 클래스로 매핑 후 순수 함수. 블록을 top→left 정렬, 블록 안 줄은 공백 하나로, 블록 사이 빈 줄. 신뢰도 필터·띄어쓰기 보정 없음. 인식 텍스트 로그 금지 | 사용자가 저장 전 항상 편집. 잘못된 보정이 원문 훼손보다 나쁨 |
| Q5 지금 구현 | **진행.** 조건: `TextExtractor` 인터페이스 + `MlKitTextExtractor` 별도 파일, Fake로 ViewModel 테스트, 비트맵 다운샘플링(긴 변 ~2048) + 디코드 백그라운드, `suspendCancellableCoroutine`(추가 의존성 없음), 새 권한 없음, 디코드 실패는 그 자리에서 Error. 릴리스 태그·배포는 오너 몫 | 되돌리기: 의존성 1줄 + 새 파일 + ViewModel 분기 1곳 |

## 오너 몫으로 남긴 것
- 번들 전환 여부(APK 크기 판단). 전환은 `libs.versions.toml` 좌표 한 줄.
- ~~설정 화면 Gemini 키 입력 UI + 전송 동의 문구~~ → 구현됨(자율 루프 후속 PR): 설정의 "AI 정밀 분석(선택)" 카드에서 키 등록(fail-closed,
  백업 미포함 안내) + "사진이 Google Gemini로 전송됨" 동의 체크. OCR 화면은 둘 다 있을 때만 "정밀 분석" 버튼을 보이고,
  사진마다 확인 다이얼로그 → 결과 다이얼로그에서 "이 결과로 바꾸기"를 눌러야 편집창에 반영(Q3 (c) 그대로). 오너 사후 확인 대상.
- `metadata.json` 문구, Room 스키마, Room DB 백업 포함 여부.

## 가장 강력한 반대(기록)와 그럼에도 진행한 이유
- 반대(A·B·C 공통): **한국어 인식 품질을 아무도 측정하지 않은 채** 유일한 결과 경로를 바꾼다. 품질이 낮으면 "가짜라도 나오던 기능"이 "빈 화면"이 되어 오너 눈에 후퇴로 보일 수 있고, 제품 톤 변경을 오너 부재 중 하는 셈이다.
- 진행 이유: 현재 상태는 모든 사용자가 매번 가짜 인용문을 받고 저장할 수 있는 상태이며 이는 시간이 갈수록 되돌릴 수 없다. ADR-001이 이 상태를 "2단계 A 전까지의 과도기"로 명시했고 2단계 A는 오너가 채택했으므로 새 톤을 정하는 것이 아니라 정해진 톤으로 옮기는 것이다. 인식 엔진은 인터페이스 뒤에 격리돼 교체 가능하고, 배포는 오너 확인 후.

## 후속 발견(이번 범위 밖)
- `cacheDir`의 촬영 원본(`camera_photo_*.jpg`)이 삭제되지 않는다.
- ML Kit SDK는 이미지를 전송하지 않지만 버그 수정·모델 갱신·사용 통계 목적의 통신은 있을 수 있다(약관). "이미지 유출 0"은 확실, "네트워크 0"은 아님.
