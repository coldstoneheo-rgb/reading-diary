- 상태: **채택** · 2026-11-02
- 결정 방식: 오너 답(2026-10-03) «기억 서랍 2단계 + Play 내부 테스트»를 받아 포트폴리오 조정(LC)이 회의(G2)에서 분기 C(병행)를 합의·채택했다.
  이 문서는 그 결정과 ADR-003·ADR-004에 남아 있던 오너 보류 질문 11건의 처분을 저장소 안에 기록한다.
  (회의록 정본은 저장소 밖 `life-coordinator/docs/meetings/MEETING-2026-1003-reading-diary.md`. 이 문서는 그 결정 사항만 옮긴다.)
- 상위 결정: [ADR-001](ADR-001-gemini-key-and-ocr-cost-model.md) · [ADR-002](ADR-002-on-device-ocr-rollout.md) ·
  [ADR-003](ADR-003-memory-drawer-and-honest-features.md) · [ADR-004](ADR-004-reading-knowledge-base-architecture.md)
- 근거 파일:줄은 2026-11-02 origin/main `47900e1` 기준. **개정 2026-11-03**(오너 결정, [ADR-006](ADR-006-phrase-recall-photo-storage.md) · 정본 life-coordinator `DEC-2026-1103-rd-phrase-recall.md`): §2 스키마 동결 시작 시점과 ADR-006 예외 1건 · §3·§6 ADR-004-4 `Migration(2,3)` 서술 · §6 ADR-003-5·ADR-003-6b. 원래 결정 문장은 고치지 않고 개정 표시를 붙였다.

## 배경

ADR-004 1단계(PR #20·#22·#23)가 2026-09-07에 머지된 뒤 저장소 커밋은 0이다. 오너는 다음 목표로 «기억 서랍 2단계 + Play 내부 테스트»를 골랐다.
2단계 코드(에이전트)와 출시 준비(오너 손: 키스토어·콘솔·아이콘·처리방침)는 서로 막지 않으므로 **병행**하고,
2단계 코드가 머지된 시점에 서명 AAB를 **1회** 올린다. 프로덕션 승급은 이 ADR 범위 밖이다.

## §1 패키지와 앱 이름

| 항목 | 결정 | 현재 값(근거) |
|------|------|---------------|
| applicationId | **`com.woodpeckerai.readingdiary`로 변경** | `com.example` (`app/build.gradle.kts:14`) — Play는 `com.example` 접두를 받지 않는다 |
| 코드 패키지·`namespace` | **`com.example` 유지**(power-of-habit 선례) | `namespace = "com.example"` (`app/build.gradle.kts:10`) |
| 앱 이름 | **«독서 다이어리»** | `app/src/main/res/values/strings.xml` `app_name` |

- applicationId는 첫 업로드 후 **영구히 바꿀 수 없다.** 변경은 첫 AAB 업로드 전에 끝낸다(→ [STAGE2-PLAN ⑤](../STAGE2-PLAN-2026-11.md)).
- applicationId가 바뀌면 기기에서는 **다른 앱**이다. 오너 기기에 깔린 `com.example` 설치본의 기록은 새 앱으로 넘어가지 않는다(두 앱이 나란히 깔림).
  옮기려면 2단계 ② 마크다운 내보내기로 사본을 뽑아 두는 수밖에 없고, 그 사본은 앱으로 다시 들여오지 못한다(가져오기 없음). (2026-11-03 개정: 첫 업로드 전 P5 «DB+사진 zip 백업 + 가져오기» 추가 — [명세 §3.6](../PHRASE-RECALL-SPEC-2026-11.md). 단 `com.example` 설치본은 v2·P5 이전 빌드라 zip을 만들 수 없으므로 이 문장은 그 설치본에 대해 그대로 유효하다.)
- `namespace`를 유지하므로 `BuildConfig`·`R`의 패키지는 그대로 `com.example`이다. 매니페스트의 `${applicationId}.fileprovider`(`AndroidManifest.xml:28`)와
  `context.packageName` 기반 authority(`OcrDiaryScreen.kt:140`)는 자동으로 따라간다.

## §3 2단계 묶음 경계

2단계에 **들어가는 것**:

1. **캔버스 보조 뷰** — ADR-003 Q3 2단계의 이분 그래프(책 열 ｜ 공유 단어 열). 기존 «연결 발견» 리스트를 **대체하지 않고** 보조 뷰로 얹는다.
   좌표는 순수 함수, 힘 기반 레이아웃 배제, 상한 책 10·단어 12·엣지 40(ADR-003 Q3). 엣지/단어 탭 → 원문 구절 카드.
2. **SAF 마크다운 내보내기 — 새 파일 생성만.** 사용자가 고른 폴더 아래 전용 하위 폴더, 책당 1파일 + 인덱스 1장(ADR-004 Q6).
   같은 이름 파일이 있으면 **건너뛰고** 결과 다이얼로그에 목록으로 보인다(ADR-004 Q7). 덮어쓰기·병합 0.
3. **링크 = 공유 단어 + `#태그`.** 그래프·내보내기의 링크 출처는 `KeywordLinks.build`(`data/knowledge/KeywordLinks.kt:42`)가 이미 만드는
   공유 단어(자동 추출 + `#태그`, `KeywordExtractor.kt:32` `HASHTAG`)뿐이다. LLM 제안·임베딩 0.
4. 내부 테스트 선행 정리 — ADR-003-1 «예시 2권 넣기», ADR-003-2 Unsplash 폴백 제거, §1 applicationId 변경(아래 §6 처분).

2단계에 **들어가지 않는 것**: **볼트 병합(기존 파일 수정) 없음** — 3단계 ⑦. 태그 정식 컬럼·`Migration(2,3)` — 3단계 ⑧. (**개정 2026-11-03, ADR-006:** Room 마이그레이션 서술 = **태그 + `diary_photos`.** `diary_photos`는 `Migration(2,3)`으로 첫 업로드 **전**에 들어오고(ADR-006 예외), 태그 정식 컬럼은 그대로 3단계 ⑧ — 그때 마이그레이션은 `Migration(3,4)`.)
LLM 키워드 제안 — 3단계 ⑥. 유료·광고 코드 0. 사진 외부 전송 경로 추가 0(기존 정밀 분석 경로 외). (개정 2026-11-03: «자동» 전송 경로 추가 0 — 사용자가 실행하는 P5 zip 백업(SAF)은 예외, ADR-006 Q-b)

## §4 네이버 키 APK 포함과 재검토 조건

- **결정(기본값):** 내부 테스트 빌드에는 네이버 검색 키를 APK에 포함한다. 경로는 CLAUDE.md의 ③ `.env` → `BuildConfig.NAVER_*`
  (`AddEditBookScreen.kt:834-842` `resolveNaverCredentials`: SecureKeyManager → `ENV_NAVER_*` → `NAVER_*`). 키 입력 UI는 만들지 않는다(ADR-003 실행 7 오너 결정).
- **왜 허용하는가:** 네이버 검색(도서) API는 무료 일일 한도(앱 안 안내 문구 기준 25,000건, `AddEditBookScreen.kt:207`) 방식이라 키가 뽑혀도
  **청구가 아니라 한도 소진**이 최악이다. ADR-001의 «유료 키 바이너리 금지»와 충돌하지 않는다. 테스터 ≤5명이면 정상 사용량은 한도의 1% 수준 이하로 추정한다(추정 근거: 2글자 이상 입력 후 400ms 디바운스마다 1회 호출(`AddEditBookScreen.kt:172-173`)이라 책 1권 등록에 수~십여 회, 5명 × 하루 수 권 ≈ 수백 회 이하 — 실측 아님).
- **키가 없거나 placeholder 값이면**(`resolveNaverCredentials`가 null): 공용 Google Books로 검색한다(`AddEditBookScreen.kt:219-223`, 키 없음). **무효 키(401/403/429)나 헤더에 쓸 수 없는 키는 폴백하지 않고 오류 안내만 보인다**(`:177-217`). 이 경로도 검색어가 외부로 나간다 — 데이터 안전 폼에 함께 선언.
- **재검토 조건(하나라도 해당하면 다시 결정):** ① 프로덕션 또는 공개/비공개 테스트로 넓힐 때(필수) ② 테스터가 429(한도 초과) 안내를 보고할 때
  ③ 네이버 개발자센터 사용량이 테스터 수로 설명되지 않게 늘 때 ④ 네이버 API 약관이 클라이언트 내장 키를 금지하는 것으로 확인될 때.
  재검토 선택지는 서버 프록시(ADR-001 B와 같은 서버 부담) 또는 Google Books 전용 전환.

## §6 오너 보류 11건 처분

ADR-003 보류 6건 + ADR-004 보류 5건 = 11건. ADR-003 보류 6은 질문 두 개(스토어 부제 + 위키링크 유지)를 담고 있어 **행을 6a·6b로 나눴다**(처분 12행).
원문 질문은 고치지 않는다. 원문 위치: ADR-003 `:34-39`, ADR-004 `:57-61`.
