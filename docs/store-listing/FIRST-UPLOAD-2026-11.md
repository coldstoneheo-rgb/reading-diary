## 1. 업로드 키 만들기 — 10분

시작 메뉴 › PowerShell을 새로 열고(Claude 창 · Git Bash 아님) 1줄:

```
cd C:\Users\colds\reading-diary; & "C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe" -genkeypair -v -keystore my-upload-key.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000
```

비밀번호 2번(화면에 안 보임) → 이름 등은 Enter → 마지막 «맞습니까?»에 `y`. 키 비밀번호를 따로 물으면 Enter(같은 값). **«이미 있습니다»가 나오면 멈춘다**(덮어쓰지 않는다).
- **됐는지:** 1줄을 치고 비밀번호를 넣으면 `upload`와 `PrivateKeyEntry`가 보인다.

```
& "C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe" -list -keystore my-upload-key.jks
```

## 2. 키 사본 두 곳 — 5분

`my-upload-key.jks`를 ① PC 밖 저장 장치 ② 본인만 보는 클라우드 폴더에 복사한다. 레포 안 다른 폴더 · 채팅 · 메일에는 두지 않는다(공개 레포 — git이 무시하는 것은 루트의 이 이름뿐, `.gitignore:25`).
- **됐는지:** 두 사본의 크기가 원본과 같고, 비밀번호가 비밀번호 관리자에 있다.

## 3. 콘솔에서 앱 만들기 — 10분

play.google.com/console › «앱 만들기» → 답안지 §4-1의 이름 · 패키지 이름 · 언어 · 앱 · 무료 · 연락 메일 → 선언 2개 · Play 앱 서명 약관 → «앱 만들기».
패키지 이름은 바꾸거나 다시 쓸 수 없다(9859152 «can't be deleted or re-used»).
- **됐는지:** 앱 목록에 «독서 다이어리»가 있고 대시보드가 열린다.

## 4. 카카오 키 정하기 — 10분

답안지 §3 «필수»를 읽고 ① 지금 키 그대로 ② 릴리스 전용 새 키 가운데 고른다(권고 ②). ②면 developers.kakao.com › 내 애플리케이션 › 앱 › 앱 키 › REST API 키 «키 추가» → 메인 체크아웃 `.env`의 `KAKAO_REST_API_KEY` 값을 바꾼다(값을 대화 · 커밋에 쓰지 않는다).
- **됐는지:** 고른 번호를 LC에 말했고, ②면 카카오 콘솔에 새 키가 보인다.

## 5. 처리방침 게시 — 3분

워커가 `gh-pages` 가지(처리방침 한 파일)를 올린 뒤: GitHub 레포 › Settings › Pages › Source «Deploy from a branch» › `gh-pages` / root › Save. (사용자가 승인하면 워커가 대신할 수도 있다.)
- **됐는지:** 몇 분 뒤 `https://coldstoneheo-rgb.github.io/reading-diary/privacy-policy.html`이 시크릿 창에서 열린다 → 워커가 앱 안 주소 1줄 PR을 낸다.

## 6. 등록정보 + 그림 — 15분

사용자 증가 › 스토어 등록정보 › 기본 등록정보: 앱 이름 · 짧은 설명 · 전체 설명(답안지 §4-1) · 아이콘 · 1024×500 · 휴대전화 스크린샷 4장(답안지 §4-4) → 저장. 카테고리 «도서/참고자료»와 연락 메일은 스토어 설정에서.
- **됐는지:** 대시보드의 «스토어 등록정보 설정» 항목에 완료 표시가 있다.

## 7. 앱 콘텐츠 · 데이터 보안 — 25분

정책 및 프로그램 › 앱 콘텐츠에서 위에서 아래로: 처리방침(5의 주소) · 광고 · 로그인 정보 · 콘텐츠 등급 · 타겟 연령 · 뉴스/정부/금융/건강 · 광고 ID · 데이터 보안 → 답안지 §4-2 · §4-3을 그대로.
- **됐는지:** «조치 필요» 탭이 비었다.

## 8. 서명 빌드 — 15분

답안지 §6의 두 블록을 **한 블록씩** Git Bash 창에서.
- **됐는지:** `BUILD SUCCESSFUL`이 나오고 `app/build/outputs/bundle/release/app-release.aab`가 방금 시각으로 있다. 첫 블록의 커밋이 워커가 알려 준 SHA와 같다.

## 9. 구글 그룹 만들기 — 5분

groups.google.com › 그룹 만들기 → 그룹에 가입할 수 있는 사용자 «웹상의 모든 사용자», 대화 · 구성원을 볼 수 있는 사용자는 소유자/관리자. 그룹 방식은 LC 가정이라 바꿔도 된다.
- **됐는지:** 시크릿 창에서 다른 구글 계정으로 가입 버튼이 보인다.

## 10. 비공개 트랙 → 검토로 보내기 — 15분

테스트 및 출시 › 테스트 › 비공개 테스트 › 트랙 관리: 국가 «대한민국» → 테스터 «Google 그룹스»에 그룹 주소 · 의견 받을 곳 → 새 버전 만들기 → AAB 올리기(앱 서명은 기본값) → 출시 노트(답안지 §6) → 저장 → 게시 개요 › «검토를 위해 보내기».
- 비공개 첫 제출에는 관리형 게시를 쓸 수 없다(9859654).
- **됐는지:** 게시 개요에 «검토 중»이 보인다. 그 뒤로는 검토가 끝날 때까지 아무것도 더 보내지 않는다(줄 뒤로 밀릴 수 있다).

검토가 끝나 상태가 «게시됨»이 되면: 참여 링크를 본인 계정으로 열어 본 뒤 모집 글(답안지 §7)을 한 번 올린다.
