## 1. 업로드 키 만들기 — 10분

시작 메뉴 › PowerShell을 새로 열고(Claude 창 · Git Bash 아님) 1줄:

```
cd ~\reading-diary; & "C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe" -genkeypair -v -keystore my-upload-key.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000
```

비밀번호를 먼저 정해 비밀번호 관리자에 저장한다 — 6자 이상, **영문 · 숫자 위주**(한글은 8단계에서만 실패할 수 있다). 비밀번호 2번(화면에 안 보임) → 이름 등은 Enter → 마지막 «맞습니까? / Is CN=… correct? [no]»에는 Enter가 아니라 `y`. 키 비밀번호를 따로 물으면 Enter(같은 값). **«이미 있습니다 / already exists»가 나오면 멈춘다**(덮어쓰지 않는다).
- **됐는지:** 1줄을 치고 비밀번호를 넣으면 `upload`와 `PrivateKeyEntry`가 보인다.

```
& "C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe" -list -keystore my-upload-key.jks
```

## 2. 키 사본 두 곳 — 5분

`my-upload-key.jks`를 ① PC 밖 저장 장치 ② 본인만 보는 클라우드 폴더에 복사한다. 레포 안 다른 폴더 · 채팅 · 메일에는 두지 않는다(공개 레포 — git은 이 이름의 파일을 어느 폴더에서든 무시하지만(`.gitignore:25`), 이름이 바뀐 사본은 무시하지 않는다).
- **됐는지:** 두 사본의 크기가 원본과 같다. 비밀번호가 비밀번호 관리자에 있다(1단계에서 저장).

## 3. 콘솔에서 앱 만들기 — 10분

play.google.com/console › «앱 만들기» → 답안지 §4-1의 이름 · 패키지 이름 · 언어 · 앱 · 무료 · 연락 메일 → 선언 2개 · Play 앱 서명 약관 → «앱 만들기».
패키지 이름은 바꾸거나 다시 쓸 수 없다(9859152 «can't be deleted or re-used»).
- **됐는지:** 앱 이름 아래가 글자 그대로 `com.woodpeckerai.readingdiary`이고 기본 언어가 한국어다(기본값은 영어라 놓치기 쉽다).

## 4. 카카오 키 정하기 — 10분

답안지 §3 «필수»를 읽고 ① 지금 키 그대로 ② 릴리스 전용 새 키 가운데 고른다(권고 ②). ②면 developers.kakao.com › 내 애플리케이션 › 앱 › 앱 키 › REST API 키 «키 추가»(허용 IP는 비워 둠 · 제품 설정에서 Daum 검색이 켜져 있는지 확인) → 메인 체크아웃 `.env`의 `KAKAO_REST_API_KEY` 값을 바꾼다(값을 대화 · 커밋에 쓰지 않는다).
- **됐는지:** 고른 번호를 LC에 말했다. ②면 카카오 콘솔에 새 키가 보이고, `.env`를 메모장으로 열었을 때 `KAKAO_REST_API_KEY=` 줄이 하나이며 값이 새 키다(빌드는 틀려도 경고하지 않는다).

## 5. 처리방침 게시 — 3분

(워커) 게시하는 날 `gh-pages` 사본과 원본 `docs/privacy/privacy-policy.html`의 `[게시일 입력]`을 **같은 날짜**로 채운다.

① 사용자가 LC에 «게시해도 됨»이라고 말한다 → ② 워커가 `gh-pages` 가지(처리방침 한 파일)를 올린다 → ③ 사용자가 GitHub 레포 › Settings › Pages › Source «Deploy from a branch» › `gh-pages` / root › Save. (사용자가 승인하면 워커가 대신할 수도 있다.)
- **됐는지:** 몇 분 뒤 `https://coldstoneheo-rgb.github.io/reading-diary/privacy-policy.html`이 시크릿 창에서 열리고 **시행일이 날짜로, 문의 메일이 주소로** 보인다(`[ ]` 자리가 남지 않음) → 워커가 앱 안 주소 1줄 PR을 낸다.

## 6. 등록정보 + 그림 — 15분

사용자 증가 › 스토어 등록정보 › 기본 등록정보: 앱 이름 · 짧은 설명 · 전체 설명(답안지 §4-1) · 아이콘 · 1024×500 · 휴대전화 스크린샷 4장(답안지 §4-4) → 저장. 카테고리 «도서/참고자료»와 연락 메일은 스토어 설정에서.
- **됐는지:** 대시보드의 «스토어 등록정보 설정» 항목에 완료 표시가 있다.

## 7. 앱 콘텐츠 · 데이터 보안 — 25분

정책 및 프로그램 › 앱 콘텐츠에서 위에서 아래로: 처리방침(5의 주소) · 광고 · 로그인 정보 · 콘텐츠 등급 · 타겟 연령 · 뉴스/정부/금융/건강 · 광고 ID · 데이터 보안 → 답안지 §4-2 · §4-3을 그대로.
- **됐는지:** «조치 필요» 탭이 비었고, 데이터 보안을 내기 전 미리보기에 **검색 기록 · 사진 · 진단/성능 · 기기 ID 네 가지**가 모두 보인다(안 보이면 «일시 처리»를 잘못 고른 것 — 10787469).

## 8. 서명 빌드 — 15분

시작하기 전에 LC에 «워커 창이 쉬는지»를 묻는다. 답안지 §6에서 `cd ~/reading-diary`로 시작하는 블록, 그다음 `unset …`로 시작하는 블록을 **한 블록씩** Git Bash 창에서.
- **됐는지:** `BUILD SUCCESSFUL`이 나오고 `app/build/outputs/bundle/release/app-release.aab`가 방금 시각으로 있다. 첫 블록의 커밋이 워커가 알려 준 SHA와 같다. (선택) `keytool -printcert -jarfile`로 AAB의 서명이 1단계 키인지 본다.

## 9. 구글 그룹 만들기 — 5분

groups.google.com › 그룹 만들기 → 그룹에 가입할 수 있는 사용자 «웹상의 모든 사용자», 글쓰기 · 대화 보기 · 구성원 보기는 소유자/관리자만(회원이 글을 쓰면 모두에게 메일이 갈 수 있다). **적어 둘 것 3개: 그룹 주소(`…@googlegroups.com`) · 가입 링크 · 의견 받을 곳(기본값 = 문의 메일).** 그룹 방식은 LC 가정이라 바꿔도 된다.
- **됐는지:** 시크릿 창에서 다른 구글 계정으로 가입 버튼이 보인다.

## 10. 비공개 트랙 → 검토로 보내기 — 15분

테스트 및 출시 › 테스트 › 비공개 테스트 › 트랙 관리: 국가 «대한민국» → 테스터 «Google 그룹스»에 그룹 주소 · 의견 받을 곳 → 새 버전 만들기 → AAB 올리기(앱 서명은 기본값) → 출시 노트(답안지 §6) → 미리보기에 **오류**가 있으면 멈추고 캡처, 경고뿐이면 캡처만 보내고 계속 → 저장 → 게시 개요 › «검토를 위해 보내기».
- **versionCode는 한 번 올리면 다시 못 쓴다** — 올린 뒤 고치려면 워커가 +1 PR을 먼저 낸다(같은 AAB를 다시 올리지 않는다).
- 비공개 첫 제출에는 관리형 게시를 쓸 수 없다(9859654).
- **됐는지:** 게시 개요에 «검토 중»이 보인다. 그 뒤로는 검토가 끝날 때까지 아무것도 더 보내지 않는다(줄 뒤로 밀릴 수 있다).

## 11. 본인 기기 확인 → 모집 글 — 25분

검토가 끝나면 트랙 › 테스터 탭에 참여 링크가 생긴다. 모집 글보다 **먼저** 본인 휴대폰에서(실기기 확인은 여기서 처음이다 — 문제를 테스터보다 먼저 본다):
1. 지금 디버그 앱의 설정 «백업 파일 만들기» → zip이 두 곳에 있고 크기가 0이 아닌지 본 뒤 → 디버그 앱 삭제(서명이 달라 덮어 설치할 수 없다).
2. 그룹 가입 → 참여 링크 → Play로 설치.
3. 책 검색 1회(카카오 키가 없다는 안내가 없는지도 본다) · 쪽 1장 촬영 인식 · 저장 1회 · 낱말로 찾기 1회 · 설정에서 처리방침 링크 열기.
4. **밑줄 칩(실기기 확인은 처음):** 밑줄 친 쪽 1장을 인식하면 편집창 아래에 칩 카드가 뜨고 밑줄 어절이 켜져 있다 · 칩을 켜고 꺼도 «고른 어절로 문장 바꾸기»를 누르기 전에는 글이 그대로다 · 밑줄 없는 쪽에서는 카드가 없다. (버튼은 손으로 고친 글까지 덮고 되돌리기가 없다 — 알려진 한계)
5. «백업 파일에서 복원».
- **됐는지:** 3의 다섯 가지 · 4의 세 가지 · 5가 모두 된다. 하나라도 안 되면 글을 올리지 말고 캡처를 보낸다.
- 그 뒤 모집 글(답안지 §7)을 한 번 올린다.
