# 화면 밀도 재설계 계획(2026-11-27 · HO-2026-1127 조건 2)

> 사용자 실기기 지적 4번(여백 · 크기 · 병기 · 위치)과 1번(읽기 시작 흐름)을 받는 계획서. 이 문서가 «계획 가»를 받은 뒤에 재설계 구현 PR을 연다(조건 6).
> 사용자 사진 · 영상 · 그 안의 글은 이 문서에 없다. 레퍼런스 앱은 **밀도와 동선의 본보기**로만 쓴다 — 색 · 아이콘 그림 · 화면 생김새는 옮기지 않는다.
> 캡처는 레포 밖 사용자 열람 폴더에 둔다(`before/` · `after-c345/` · 구현 PR마다 `after-rN/`, 같은 파일 이름 = 짝).

## 0. 독자와 지키는 것

- 독자: 책을 읽다 한 손으로 폰을 드는 사람. 기록 한 건을 30초 안에 끝내려 한다. 지금 테스터 12명과 새해에 처음 여는 사람이 같은 화면을 본다.
- 그대로 두는 것: 색 3층(바깥 배경 · 중간 · 내용) · 본문 글자 크기(줄이지 않는다 — 줄이는 것은 여백과 상자).

## 5. 레퍼런스에서 따르는 것 / 따르지 않는 것

| 따른다 | 까닭 |
|---|---|
| 입력을 «이름표 + 값» 한 줄로 쌓기 | 첫 화면에 입력 4줄이 들어간다(지금 3칸 + 큰 안내 카드) |
| 사진을 화면 폭으로 · 사진 도구를 사진 위에 | 사용자가 직접 든 예(회전 · 반전) |
| 상세 = 작은 표지 + 한 줄 진척도 + 기록 카드 | 기록이 첫 화면에 보인다 |
| 기록 쓰기 · 갤러리를 상단 바 아이콘으로 | 본문 두 버튼(40dp + 사이 16dp)이 빠진다 |

| 따르지 않는다(반박) | 까닭 |
|---|---|
| **저장을 상단 바 ✓로** | 한 손 사용자는 오른쪽 위에 엄지가 닿지 않는다. 저장은 화면 아래 고정 버튼 하나로 둔다 — **이 한 가지는 서로 다른 작업을 낳는 갈림이라 LC 판단을 청한다**(§7) |
| 노란 단색 바 · 아이콘 그림 | 색 3층 유지 · 생김새를 옮기지 않는다 |
| 자르기를 별도 화면으로 | 지금 앱은 자르기와 인식이 한 화면에서 이어진다(뒤로 가기 · 재생성 복원 시험이 이 구조에 묶여 있다 — `CameraProcessDeathTest`). 한 화면 안에서 사진 위 도구로 줄인다 |
| 광고 띠 | 이 앱은 광고 0 |
