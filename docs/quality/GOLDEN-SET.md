# 추출 품질 기준 자료(golden) 규격 — 1쪽

목적: 목적지 «독서 지식 베이스»(LC `DEC-2026-1111` ①~⑥)의 추출 품질을 **느낌이 아니라 같은 자료의 일치율**로 잰다.
엔진(기기 ML Kit · 밑줄 검출기 · 다른 OCR · 이미지를 읽는 LLM)을 바꿔도 같은 자료·같은 수치로 다시 잰다.

**사진·정답은 레포에 넣지 않는다.** 사용자 실제 책 페이지라 레포 밖 로컬 폴더에만 둔다(기본 `D:\사진\reading-diary\golden\`).
레포에는 이 규격과 측정 코드(`app/src/test/java/com/example/golden/`)만 있다. PR·메시지에는 경로와 수치만 쓴다.

## 1. 폴더 구조

```
golden/
  <id>.jpg | .png             사진(원본 그대로 · 사진 1장 = 자료 1장)
  <id>.golden.txt             정답(아래 2)
  boxes/<출처>/<id>.tsv        글줄·어절 상자(선택). 출처 = 상자를 만든 엔진 이름, 예: tesseract-5.3.1-kor · mlkit-dump
  outputs/<엔진>/<id>.<대상>.txt  엔진이 낸 글(선택). 대상 = marks · underline · highlight · memo · page
  _results/measure.md          측정 결과(측정이 덮어쓴다)
```

`<id>`는 영문·숫자·`-`(예: `nietzsche-p135`). 실패 사례 오버레이 PNG는 `spike/`(측정 때 `RD_SPIKE_OUT`)에 쓴다.

## 2. 정답 파일 `<id>.golden.txt` (UTF-8 텍스트 — 메모장으로 고친다)

머리 줄 `이름: 값`(뒤 ` # …`는 주석) 다음에 절 4개. `#`로 시작하는 줄은 주석.

| 머리 | 뜻 |
|---|---|
| `photo` | 사진 파일 이름(같은 폴더) |
| `rotate` | 파일을 시계 방향으로 돌려야 똑바로 서는 각도 0·90·180·270 (휴대폰 사진은 EXIF로 누워 저장되는 일이 많다 — 측정 코드는 EXIF를 읽지 않는다) |
| `book` · `page` | 책 · 쪽 |
| `whole_page` | `yes` = 표기·자르기 없이 페이지 전체를 남기려던 사진(목적지 ③, 요약 대상) · `no` |
| `crop` | 앱에서 정한 틀 `l,t,r,b`(0~1) 또는 `none`(사진 전체) |

| 절 | 한 줄 형식 | 내용 |
|---|---|---|
| `[page]` | 사진의 본문 한 줄 그대로 | **본문만**(장 제목·쪽번호·머리글·출처 줄 제외). 줄 순서 = 줄번호 1, 2, … |
| `[marks]` | `줄번호<탭>underline\|highlight<탭>그 줄에서 표기한 글` | 표기한 문장·어절(목적지 ①). 여러 줄에 걸친 밑줄은 줄마다 한 행. 글은 그 줄 안의 연속 어절이어야 한다(측정 코드가 검사) |
| `[memo]` | `자리<탭>자필 메모 글` | 자리 = `title` · `margin` · `bottom` · `inline`(목적지 ④) |
| `[decoys]` | `종류<탭>줄번호(없으면 비움)` | 밑줄로 잘못 잡기 쉬운 것: `bleed`(뒷장 비침) · `decoration`(장식 막대) · `pagenum`(쪽번호 옆 선) · `memo_stroke`(자필 가로획) |

- **확신 없는 글자**는 `{?}`로 적는다(측정 때 어느 글자와도 같다고 본다). 사용자가 나중에 고친다.
- **상자 번호를 정답에 적지 않는다.** 정답은 글과 줄 순서만 — 상자↔어절 대응은 측정 코드가 만든다(엔진이 바뀌면 상자 번호가 달라지므로).

## 3. 일치율 정의

**어절** = 공백 또는 줄 끝으로 갈린 덩어리, 앞뒤 문장부호(`.,?!;:·…"'()` 등) 제거, 유니코드 NFC. 사진에서 줄 끝에 끊긴 말(«그들 / 은»)은 두 어절로 센다 — 기기 엔진도 줄 단위로 읽기 때문이다.

| 수치 | 계산 | 무엇을 보나 |
|---|---|---|
| 어절 정밀도 | 맞은 어절 ÷ 엔진이 낸 어절 (다중집합 교집합) | 표기 안 한 글을 끌어왔나(①의 «만») |
| 어절 재현율 | 맞은 어절 ÷ 정답 어절 | 표기한 글을 빠뜨렸나 |
| 글자 오류율(CER) | 편집 거리(공백 뺀 엔진 글 → 공백 뺀 정답 글) ÷ 정답 글자 수 | 잘못 읽은·빠진 글자 |

대상별 정답: `marks` = 밑줄+형광펜 · `underline` · `highlight` · `memo` · `page`(본문 전체).

**밑줄 검출 스파이크 수치**(글이 아니라 «어느 어절을 골랐나»): 정답 `[marks]`의 어절과 검출기가 고른 어절을 `(줄번호, 어절 순번)`으로 맞대어 정밀도·재현율, 미끼 줄(`[decoys]` 줄번호)의 오검출 수, 본문 밖(정답 `[page]`에 대응하지 않는 줄)의 검출 구간 수를 낸다. 어절의 가로 범위는 대응한 상자 줄 안에서 글자 폭 비례(한글 1 · 공백 0.75 · 문장부호 0.45)로 나눈다.

## 4. 엔진을 바꿔 끼워 다시 재기

1. 엔진 출력 글을 `outputs/<엔진>/<id>.<대상>.txt`로 둔다(예: 기기 앱에서 «틀 안 글자 읽기» 결과를 복사 → `outputs/mlkit-2026-11/nietzsche-p135.page.txt`). 대상별 한 파일.
2. 상자를 쓰는 검출기면 그 엔진의 줄·어절 상자를 `boxes/<출처>/<id>.tsv`로 둔다. 열은 Tesseract `tsv`와 같다(`level … left top width height conf text`, 어절 = level 5, 똑바로 세운 사진 좌표). 다른 엔진은 같은 열로 옮겨 적고 `conf`를 모르면 `-1`.
   - Tesseract(로컬, 무료, 외부 호출 0): 사진을 똑바로 세운 PNG로 바꾼 뒤 `tesseract <사진> <id> -l kor --psm 3 tsv`.
   - 기기 ML Kit: `Text.TextBlock.lines[].elements[].boundingBox`를 위 열로 덤프(후속 — 아직 덤프 경로 없음).
3. 측정(그래들, 레포 워크트리에서):

   ```
   RD_GOLDEN_DIR='D:\사진\reading-diary\golden' RD_SPIKE_OUT='D:\사진\reading-diary\spike' \
     gradle :app:testDebugUnitTest --tests com.example.golden.GoldenMeasureTest --rerun
   ```

   폴더가 없거나 비어 있으면 실패하지 않고 «자료 0장». 결과 = 표준 출력 + `golden/_results/measure.md`. 수치는 재기만 하고 테스트를 실패시키지 않는다.

## 5. 자료를 늘릴 때(사용자 손, 첫 벌 10장 안팎)

밑줄만 · 형광펜만 · 밑줄+자필 메모 · 표기 없는 문단(틀로 자름) · 표기 없는 페이지 전체 · 얇은 종이(비침 심함) · 컬러 인쇄 책 — 이 갈래가 1장 이상씩 들어가면 엔진 비교가 한쪽으로 쏠리지 않는다. 사진을 넣으면 정답 초안은 워커가 만들고 사용자가 고친다.
